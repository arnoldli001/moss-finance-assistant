# 金融量化系统故障分类体系（Failure Taxonomy）

本文档定义了金融量化交易系统中所有可能的故障类别、严重等级及对应的初步响应策略。

> **分类铁律**：错误分类不能一刀切。所有故障必须先按"是否可重试 × 是否为硬错误"四象限分类，再决定处理动作。详见 SKILL.md 第 1.2 节的四象限决策树。

## 1. 故障分类矩阵（按四象限归类）

### 象限 A：可重试的硬错误（Retryable Hard Errors）
错误由瞬态外部环境导致，重试大概率成功，无需修改请求本身。

| 类别 ID | 故障类型 | 典型场景 | HTTP/业务码 | 是否可重试 | 初步响应动作 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **F-A01** | 网络瞬态错误 | TCP RST、Connection reset、DNS 抖动 | 502/503/504 | ✅ 是 | 指数退避 + 抖动重试（最多 5 次） |
| **F-A02** | 响应超时（读） | 查询账户余额响应慢 | 408/504 | ✅ 是 | 指数退避重试，最多 3 次 |
| **F-A03** | 流控限制（未熔断） | 429 未达熔断阈值 | 429 + Retry-After | ✅ 是 | 按 Retry-After 头延迟重试 |
| **F-A04** | 行情源临时不可用 | 主行情源心跳超时 | 503 | ✅ 是 | 切备用源 + 主源后台探测 |
| **F-A05** | WebSocket 闪断 | 盘中行情断流 | 连接 1006 | ✅ 是 | 1s→2s→4s→8s→16s→30s 退避重连 |

### 象限 B：不应重试的软错误（Non-Retryable Soft Errors）
错误由请求本身的语义或业务状态导致，重试同样会失败，必须修改请求或人工介入。

| 类别 ID | 故障类型 | 典型场景 | HTTP/业务码 | 是否可重试 | 初步响应动作 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **F-B01** | 参数校验失败 | 订单价格超涨跌停、数量非整手 | 400 / INVALID_PARAM | ❌ 否 | 永不重试，直接拒绝 |
| **F-B02** | 业务规则拒绝 | 账户余额不足、持仓超限、信用不足 | 400 / INSUFFICIENT_xxx | ❌ 否 | 永不重试，告警并剔除信号 |
| **F-B03** | 撤单超限 | 单合约撤单达 500 次 | ORDER_CANCEL_LIMIT | ❌ 否 | 熔断该合约，次日恢复 |
| **F-B04** | 涨跌停限制 | 触及涨停板无法买入 | PRICE_LIMIT | ❌ 否 | 永不重试，记录后跳过 |
| **F-B05** | 订单不存在 | 撤单时订单已成交 | ORDER_NOT_FOUND | ❌ 否 | 永不重试，更新本地状态 |
| **F-B06** | 合约停牌 | 标的暂停交易 | SYMBOL_SUSPENDED | ❌ 否 | 永不重试，标记不可交易 |

### 象限 C：不可重试错误（Permanent Errors）
错误由系统级、进程级或数据级损坏导致，任何重试都不会成功，必须触发恢复机制。

| 类别 ID | 故障类型 | 典型场景 | 是否可重试 | 初步响应动作 |
| :--- | :--- | :--- | :--- | :--- |
| **F-C01** | 响应超时（写） | 下单后 3s 未收到 ACK | ❌ 否 | **严禁重试**，立即触发订单状态反查 |
| **F-C02** | 静默数据错误 | 行情时间戳错乱导致因子计算偏移 | ❌ 否（无异常抛） | 依赖交叉验证（双源比对）发现并告警 |
| **F-C03** | 系统资源耗尽 | 内存溢出（OOM）、磁盘写满 | ❌ 否 | 进程自愈（重启），依赖 WAL 恢复状态 |
| **F-C04** | 依赖服务不可用 | 风控服务、持仓数据库连接失败 | ❌ 否 | Fail-Closed（停止交易），防止裸奔 |
| **F-C05** | 数据缺失 | 某合约实时行情 Tick 中断 | ❌ 否（不可重试原源） | 切换备用行情源，标记数据源不健康 |

### 象限 D：配置类错误（Configuration Errors）—— 绝对不可重试
错误由配置、凭证、环境问题导致。重试不仅无效，还会触发券商风控告警（如 IP 封禁）。

| 类别 ID | 故障类型 | 典型场景 | HTTP/业务码 | 是否可重试 | 初步响应动作 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **F-D01** | **API Key 过期** | 券商 Token 超期 | 401 / TOKEN_EXPIRED | ❌ 否 | **永不重试**，立即告警，人工刷新凭证 |
| **F-D02** | **API Key 无效** | 错误的 AppSecret | 401 / INVALID_KEY | ❌ 否 | **永不重试**，告警 + 暂停该券商通道 |
| **F-D03** | **签名错误** | HMAC 签名校验失败 | 401 / SIGN_INVALID | ❌ 否 | **永不重试**，检查时钟同步 + 密钥配置 |
| **F-D04** | **权限不足** | 接口未授权 | 403 / NO_PERMISSION | ❌ 否 | **永不重试**，申请权限后人工恢复 |
| **F-D05** | **IP 白名单未通过** | 来源 IP 未在白名单 | 403 / IP_FORBIDDEN | ❌ 否 | **永不重试**，运维添加 IP 白名单 |
| **F-D06** | **时钟漂移** | 本地时间与交易所偏差 > 1s | TIMESTAMP_SKEW | ❌ 否 | **永不重试**，NTP 校时后恢复 |
| **F-D07** | **环境变量缺失** | .env 中关键配置缺失 | 启动失败 | ❌ 否 | **永不重试**，启动前必须校验 |

> **绝对铁律**：**401/403 = 配置问题，不是网络问题**。重试只会触发券商风控告警（如"5 分钟内 10 次无效凭证请求 → IP 封禁 24 小时"）。出现此类错误立即告警 + 停止通道，由人工/自动化流程修复配置后恢复。

## 2. 严重等级（Severity）映射

| 严重等级 | 包含类别 | 告警渠道 | 目标恢复时间（RTO） |
| :--- | :--- | :--- | :--- |
| **P0（致命）** | F-C01（写超时）, F-C02（静默错误）, F-C04（依赖全挂）, F-D01~D07（配置错误） | 电话 + 钉钉/企业微信 + 短信 | < 1 分钟 |
| **P1（严重）** | F-A01（网络断连）, F-B03（流控触发）, F-A05（WS 闪断） | 钉钉/企业微信 + 邮件 | < 5 分钟 |
| **P2（一般）** | F-A02（读超时）, F-A03（429 流控）, F-A04（行情源切换）, F-C05（数据降级） | 邮件 / 看板告警 | < 30 分钟 |
| **P3（轻微）** | F-B01/B02/B04/B05/B06（业务拒绝，非系统故障） | 日志记录 | 次日复盘处理 |

## 3. 故障冰山模型（Silent Failure）

在量化交易中，最危险的故障通常不抛出异常。请对以下静默失败保持高度警惕：

- **过期的缓存数据**：当行情源断连时，若代码静默返回 5 秒前的旧价格，策略将基于错误信号下单。**处理方式**：必须使用版本号或时间戳检查数据新鲜度，若超过阈值（如 1s），宁可抛出异常也不返回旧数据。
- **精度丢失**：浮点数运算（如 `0.1 + 0.2`）导致的价格误差，可能使风控价格判断失效。**处理方式**：价格、数量计算统一使用 `Decimal` 类型。
- **逻辑死锁**：线程池耗尽但未抛出异常，请求在队列中排队，看似正常但吞吐量归零。**处理方式**：监控线程池队列深度和拒绝策略。
