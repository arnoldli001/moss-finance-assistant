## 二、多轮对话记忆系统

### 设计目标
- 用户在同一会话中连续对话，AI 能记住上下文
- 重启服务后对话历史不丢失
- 按会话（thread_id）隔离，互不干扰

### 技术选型
| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| InMemorySaver | 简单 | 重启丢失 | ✗ |
| SqliteSaver（同步） | 持久化 | 不支持 async | ✗ |
| **AsyncSqliteSaver** | 持久化 + 异步 | 需事件循环内初始化 | ✓ |

### 架构设计
```
用户消息 → FastAPI /api/task → run_deep_agent(query, thread_id)
                                    │
                                    ▼
                          get_main_agent()  ← 惰性初始化
                                    │
                          ┌─────────┴─────────┐
                          │  AsyncSqliteSaver  │
                          │  data/checkpointer.db │
                          └─────────┬─────────┘
                                    │
                          agent.astream({messages})
                          config = {"thread_id": session_id}
                                    │
                          ┌─────────┴─────────┐
                          │  自动加载历史消息    │
                          │  + 新消息追加       │
                          │  + 状态持久化       │
                          └───────────────────┘
```

### 关键决策
- **thread_id = session_id**：会话 ID 即 LangGraph thread ID，一一对应
- **惰性初始化**：`AsyncSqliteSaver` 需要在事件循环内建立 `aiosqlite` 连接，不能在模块加载时创建
- **会话历史恢复**：`aget_state_history` 读取最新快照，过滤 tool 消息，只返回 user/assistant 可见消息

## 三、用户与会话管理

### 数据模型
```sql
users (用户表)
├── user_id        TEXT PRIMARY KEY
├── display_name   TEXT
└── created_at     TEXT

sessions (会话表)
├── session_id     TEXT PRIMARY KEY  ← 同时作为 LangGraph thread_id
├── user_id        TEXT (FK → users)
├── title          TEXT              ← 自动生成或手动重命名
├── created_at     TEXT
└── updated_at     TEXT
```

### 标题自动生成策略
```
格式：{user_id}_{关键词}_{MM-DD}
关键词：取首次 query 前 12 字符
触发时机：首条消息时（title 为 "新会话" 时自动生成）
手动重命名：PATCH /api/sessions/{id}/title（保留手动标题，不自动覆盖）
```

### 线程安全
- SQLite 默认不支持跨线程共享连接
- 用 `threading.local()` 为每个线程维护独立连接
- `check_same_thread=False` 兼容 FastAPI 线程池

## 四、WebSocket 实时通讯架构

### 消息流转
```
Agent 执行过程                    前端接收
─────────────                   ────────
main_agent.astream()
  ├ model 节点                   (静默)
  │   ├ tool_calls → task      → (静默，已隐藏)
  │   └ content → 最终结果      → task_result → 显示
  ├ 工具执行                     → (静默，已隐藏)
  ├ 子智能体调用                  → (静默，已隐藏)
  └ thinking 阶段               → thinking → 显示 💭
                                  │
                          5秒无响应 → 显示 ⏳ 进度提示
```

### 心跳与重连机制
```
┌─────────┐    ping(30s)    ┌─────────┐
│ 前端     │ ──────────────→ │ Server  │
│         │ ←────────────── │         │
│         │    pong          │         │
└────┬────┘                  └─────────┘
     │ 断开
     ▼
  onclose 触发
     │
     ├ isRunning? → 解锁 + 提示用户
     │
     └ 重连 (3次, 2s/4s/6s 指数退避)
         │
         ├ 成功 → 重置计数
         └ 失败 → 放弃
```

### 超时保护层级
| 层级 | 超时时间 | 触发动作 |
|------|----------|----------|
| 进度提示 | 5 秒 | 显示"AI 正在思考中..." |
| 进度更新 | 每 5 秒 | 更新计时文字 |
| WebSocket 重连 | 2/4/6 秒 | 自动重连 3 次 |
| 全局超时 | 5 分钟 | 强制解锁 + 提示 |

## 八、Agent 执行流程

```
用户 query
    │
    ▼
run_deep_agent(query, session_id, user_id)
    │
    ├ 1. 重置 IMA 搜索计数器
    ├ 2. 更新会话标题（首条消息自动生成）
    ├ 3. 创建会话输出目录
    ├ 4. 复制上传文件到工作目录
    ├ 5. 设置 ContextVars（session_dir + thread_id）
    ├ 6. 推送工作目录信息给前端
    │
    ▼
agent.astream({messages}, config={thread_id})
    │
    ├ model 节点
    │   ├ tool_calls → 推送 assistant_call + thinking
    │   └ content → 推送 task_result（最终结果）
    │
    ▼
finally: 清理 ContextVars
```

### 关键设计决策
- **ContextVars 传递会话上下文**：工具内部通过 `get_session_context()` 获取工作目录，不通过参数传递
- **惰性初始化 Agent**：首次调用时创建 `AsyncSqliteSaver` 连接，避免模块加载时的事件循环问题
- **递归限制**：`recursion_limit=50` 防止 Agent 无限循环
