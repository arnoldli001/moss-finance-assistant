# ADR-0003: PTD 渐进式工具披露 + 自适应门控

- 状态：已接受
- 日期：2026-08-31

## 背景

主 Agent 每轮请求全量注入所有工具的 function Schema，随工具数量线性增长。
引入 PTD（`shared/llm_client/tool_router.py`）：阶段零注入零 Schema 路由菜单让
模型选工具，执行阶段只披露子集。但引入前缺少量化依据。

## 决策

1. 新增基准 `benchmarks/bench_ptd_tokens.py`（离线、tiktoken 真实计数、
   10 个真实投研场景、协议路由与启发式兜底双路径），产出可复现数据。
2. 实测结论（2026-08-31，结果见 `benchmarks/results/ptd_tokens_latest.json`）：
   - 主 Agent 真实工具池（4 工具，全量 Schema ≈ 607 tokens）**PTD 为负优化**
     （节省 -11.7% ~ -81.4%）：路由菜单固定开销 ≈ 678 tokens 反超收益。
   - 扩展工具池（9 工具，全量 ≈ 1709 tokens）PTD 平均节省 **50.2%（协议路由）/
     53.6%（启发式）**。
3. 依据实测给 PTD 加**自适应门控**：当全量 Schema 字符数 ≤ 路由菜单字符数时
   自动旁路（跳过阶段零 LLM 调用 + 菜单注入），小工具池零浪费，大工具池保留收益。

## 后果

- 正面：收益有实测背书；小池负优化被运行时自动消除；基准可在 CI 离线复跑。
- 负面：菜单本身 ~678 tokens，压缩菜单文案可进一步降低门控阈值（待办）。

## 替代方案

- 固定开关（PTD_ENABLED=0/1）：无法随工具池规模自适应，小池负优化无保护，否决。
- 仅凭经验保留 PTD：数据不支持 4 工具池场景，否决。
